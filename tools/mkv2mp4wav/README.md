# tools/mkv2mp4wav：字幕編輯預覽 mp4 與訓練用 WAV

照目錄逐集，從 SFTP 下載影片一次，做出兩樣東西，各自驗收、各自上傳，再刪掉本機檔：

- **預覽 mp4**：給瀏覽器裡的字幕編輯器邊看邊改 SRT。參數照《字幕編輯預覽檔規格》（`kithann/字幕編輯預覽檔規格_20261027.md`）：720p、去交錯、VBR 1200／1800 kbps、每 30 格一個關鍵格、AAC 128k 單聲道、索引在檔頭。
- **WAV**：語音辨識訓練用，24 kHz、16-bit、單聲道。

兩個節目各一個指令，共用同一套核心：

| 節目 | 指令 | 目錄 | 產出 |
|---|---|---|---|
| 《開會了》 | `python3 -m tools.mkv2mp4wav.aiyalaeho` | `Kari-SRT/aiyalaeho/smkul.csv` 加 `smkul-字幕版型異常.csv` | `/home/aiyalaeho/mp4/<成果檔名>.mp4`、`/home/aiyalaeho/wav/<成果檔名>.wav` |
| 族語新聞 | `python3 -m tools.mkv2mp4wav.news` | `Kari-SRT/news/smkul.csv` | `/home/news/mp4/<年-月>/<成果檔名>.mp4`、`/home/news/wav/<年-月>/<成果檔名>.wav` |

## 怎麼跑

在這台機器的 VS Code 終端機裡，於 repo 根目錄直接打，不需要 tox 的 venv，也不用另外裝套件（只用 ffmpeg、ffprobe、sftp）：

```bash
cd /workspaces/Smkul-Kari

# 先看：全部幾集、伺服器上已經做好幾集、這次要做幾集（不下載、不建任何檔）
python3 -m tools.mkv2mp4wav.aiyalaeho --dry-run

# 先試兩集
python3 -m tools.mkv2mp4wav.aiyalaeho --limit 2

# 全部
python3 -m tools.mkv2mp4wav.aiyalaeho
```

- **停下來**：按 Ctrl+C。正在做的那集不會上傳，後面的不做，離開碼 130。
- **接著做**：再打同一行。伺服器上兩種產出都在的集數直接跳過，連下載都不用；只缺一種的只補那一種。
- **開跑前會先檢查** ffmpeg、ffprobe、sftp 找不找得到、SFTP 密碼檔（repo 根的 `.sftp-pass`）在不在、GPU 硬體編碼能不能用；缺任何一樣就在連線、下載之前停下，講出缺什麼，離開碼 2。密碼檔只看在不在，不會打開來讀。

### 關掉終端機也要繼續跑

新聞全跑要十幾天，終端機一關程式就會停（容器裡沒有 tmux）。改用這樣發動，終端機可以關：

```bash
cd /workspaces/Smkul-Kari
setsid nohup python3 -m tools.mkv2mp4wav.news > /dev/null 2>&1 &

# 看進度（隨時可以打開來看、Ctrl+C 只是停止看，不會停掉程式）
tail -f "$(ls -t kithann/mkv2mp4wav/news/*.log | head -1)"

# 真的要停掉它
pkill -INT -f 'tools\.mkv2mp4wav\.[n]ews'
```

所有終端機會印的內容都寫在紀錄檔裡，所以輸出丟掉（`/dev/null`）不會漏看任何東西。

## 看進度

開跑時先印一行總數，之後每做完一集印一行：

```
全部 3153 支，已完成 1200 支（預覽檔與音檔都在），這次要做 1953 支
[第 1203／3153 支] 20210203_012_午間_Amis_阿美 成功 用時 6 分 12 秒｜這次已做 3／1953 支，預計還要 201 小時 30 分
```

- **預計還要多久** ＝ 最近 10 集真的有做的平均用時 × 剩下要做的集數。成功、失敗都算（都花了下載和轉檔的時間）；伺服器上已經有、直接跳過的不算，否則續跑時跳過的那幾百集（每集一兩秒）會把預估拉成不到一小時。只看最近 10 集，網路或伺服器變慢時，大約一小時內預估就會跟上。
- 第一集做完之前沒有依據，印「預計時間：第一支做完後估算」。
- 結束時印總用時與成功、失敗、已存在各幾集。
- 加 `--limit` 時，「全部」是限制後的集數。

## 產出在哪、失敗了去哪看

```text
kithann/mkv2mp4wav/
├── aiyalaeho/
│   ├── 1123-1530.log             每集的 ffmpeg／sftp 錯誤輸出全文＋進度行
│   └── 1123-1530.manifest.json   對照表，每做完一集就重寫一次
└── news/
    └── …
```

對照表每集一筆（鍵是 `srt_name`），跑到一半也是完整的 JSON，頂層 `已收尾` 為 `false`，正常跑完為 `true`。每筆記：來源在哪、多大、幾格；選了第幾條音軌、平均音量；預覽檔與音檔各自的遠端路徑、位元組數、驗收（`通過` 或不通過的項目清單）、結果；預覽檔另記走哪條編碼路徑、兩邊影格數。

做沒做完**不記在 Kari-SRT**：伺服器上有沒有最終名稱就是答案。

## 它保證什麼

- **驗收不過就不上傳。** 預覽檔要過規格書第四節全部項目：影格數與來源完全相等、影像與聲音的起點與來源相同、時長差 0.1 秒內、h264 High yuv420p 1280×720 30000/1001 逐行、一條 AAC 單聲道 48 kHz、沒有時間碼軌、索引在檔頭、關鍵格間距不超過 1.1 秒、大小不超過 (1800+128) kbps × 時長。音檔要是 pcm_s16le 24000 Hz 單聲道一條音軌，樣本數等於來源解碼後樣本數的一半（差 1 個以內）。不過的項目全部列在紀錄裡。
- **兩樣各管各的。** 音檔不過，預覽檔照樣上傳；這集記失敗並講出是哪一樣。
- **上傳不會留下看起來完成的檔。** 先傳到 `.partial`，位元組數對上才改名。
- **本機只留一集。** 不管成功、失敗、被中斷，這集的來源、mp4、wav 都刪掉才做下一集。
- **一集失敗不停整批。** 記下原因做下一集；跑完有任何失敗，離開碼 1。編碼跑滿來源時長還沒結束算卡住，那集記失敗。
- **同一個來源每次轉出逐位元相同的 WAV**（不加抖動、檔頭不帶 ffmpeg 版本）。

## 聲音與音軌

- **音軌選第一條有聲音的**：從第一條開始量整條平均音量，第一條高於 −80 dB 的就用它（通常只量第一條）。開會了 107 的原檔第一條是靜音、聲音在第二條，「只取第一條」會做出整集靜音。全部靜音時音檔記失敗、預覽檔用第一條。
- **mkv 的聲音必須是 FLAC**：mkv 不記 AAC 開頭要略過的樣本數，解碼會整段偏移。**mp4 的 AAC 可以**（開會了的 20 集 mp4 都是），mp4 有記，ffmpeg 解碼時照著略過。
- 不是單聲道、聲音起點不是 0 → 音檔記失敗，不混音、不平移。

## 編碼路徑

預設只用 GPU（VAAPI），依來源自動選：

| 路徑 | 什麼來源 | 做法 |
|---|---|---|
| 硬體 | 4:2:0（新聞、開會了 mkv） | 解碼、去交錯、縮放、編碼全在 GPU，規格書 3.1 |
| 混合 | 其他（開會了 mp4 的 H.264 4:2:2，GPU 解不了） | CPU 單執行緒解碼，其餘在 GPU |
| 軟體 | 只有加 `--software` | 整批 libx264，規格書 3.2 |

**`--software` 何時用**：這台機器沒有 GPU，或 GPU 驅動出了問題。單集硬體編碼失敗時不會自動改用軟體（驅動壞掉時整批會悄悄吃滿 CPU）；跑完看對照表，再加 `--software` 重跑同一行，已上傳的會自動跳過、只補失敗的。

預覽檔沒有時間碼軌；起點跟來源相同（例如新聞 `20210101_001_午間_Rukai_魯凱` 影像從 0.033 秒開始，預覽檔也一樣，不補黑畫面）。這兩點與規格書原文不同，是 2026-11-23 的裁定。

## 新聞

```bash
cd /workspaces/Smkul-Kari
python3 -m tools.mkv2mp4wav.news --dry-run      # 全部 3153 集、已完成幾集（列伺服器約 1 分鐘）
python3 -m tools.mkv2mp4wav.news --limit 2      # 先試兩集
python3 -m tools.mkv2mp4wav.news                # 全跑（十幾天；要關終端機就用上面 setsid nohup 的寫法）
```

- 來源依序找定稿區 `/docker/news/mkv/<年-月>/`、暫放區 `/home/news/mkv/<年-月>/`、目錄的 `原始影片檔案位置`；只有伺服器明講「找不到」才換下一處，連線錯誤就記這集失敗。退到原始位置時會印出實際用的路徑。三處都沒有就記失敗並列出三個路徑。
- 產出的 `<年-月>` 取自成果檔名，不是影片所在的資料夾（原始位置 `/home/mkv-raw/9月/…` 的那集，產出照樣放 `2024-10/`）。
- 開場對兩個產出根的每個月份資料夾各列一次（48 個月 × 2，約 1 分鐘），之後每集上傳前再各問一次伺服器，所以另一台機器先傳上去的也會跳過。
- 新聞封存檔的聲音抽查 300 集全是 FLAC 單聲道；遇到不是的，那集音檔記失敗，跑完看對照表再決定。

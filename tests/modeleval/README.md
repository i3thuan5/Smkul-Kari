# tests/modeleval/：用《開會了》OCR 字幕評測 AI 模型的測試

`scripts/modeleval/`：把《開會了》燒印字幕當標準答案，量 sapolita（whisper 族語辨識）的 WER／CER，與翻譯服務兩個方向的 BLEU／chrF++。全部離線、fixture 合成，服務用假的頂替。

檔名鏡射模組名；這張表照流程排。scenario 寫的是量到的資料性質與踩過的坑。

| 模組 | scenario | 測試檔 |
|---|---|---|
| pairs | SRT 時間 `00:01:02,050` 用逗號分毫秒，當小數點會差 1000 倍；正本 CSV 有 BOM，第一欄名變 `﻿成果檔名` 就讀不到；smkul 只寫 `ami` 的集 sapolita 不收（選單只有五個語言別），照新聞線保底送海岸；兩個服務的語別碼不同套，南勢在 sapolita 是 `ami-x-iams`、在翻譯服務是 `ami_Sout`（Sout 不是「南部」，南部是恆春 `ami_Heng`）；翻譯服務收到不認得的碼不報錯、靜靜用海岸翻，所以表裡沒有的碼要擋；同一句在一集出現好幾次只問一次，族語列空的不送 | `test_pairs.py` |
| mtboth | 華→族 `translate_1` 的參數順序是 [原文, zho_Hant, 族語碼]，跟族→華 [原文, 族語碼, zho_Hant] 相反；兩個方向的語別下拉選單是不同元件（trigger 7／17），各自要握手；沒握手送非預設碼會靜靜變海岸；兩次請求之間要停；斷掉重跑不可重問快取有的句 | `test_mtboth.py` |
| asr_run／mt_run | sapolita 回傳的 SRT 原樣存（族語、華語兩列、`ʼ` 都不改），正規化是計分那步的事；暫存 mp3 做完就刪；做過的集、翻過的句不重送 | `test_run.py` |
| metrics | 64 組 golden 向量（17 組手算），兩份獨立實作逐條對過 sacrebleu v2.4.3／jiwer 3.0.4 原始碼；sapolita 與翻譯服務輸出 `ʼ`（U+02BC）、OCR 用 ASCII `'`，不統一每個有喉塞音的詞都算錯；sapolita 用 `⌃`（U+2303）寫 `^`（8 集 63 個），沒對照會被當詞的分界、`mido⌃do` 拆成兩個詞；字幕與 sapolita 標 `^` `:` 很不一致（字幕 588／193 個、sapolita 63／15 個），主要數字拿掉，但 `'` 兩邊都寫、混在一起刪會把 `'` 的錯也蓋掉；翻譯服務華語輸出裡族語名字的 `ʼ` 是 Lm 類、P*／S* 規則刪不掉，OCR 的 `'` 卻會被刪；OCR 族語列夾的漢字直接刪會把 `kako施ko` 黏成 `kakoko`；13a 會把 `^` `:` 切成獨立 token；jiwer 的 CER 先去首尾空白（`" ab"` 對 `"ab "` 是 0/2，不是 2/3）；替換／刪除／插入三個數要來自同一個最小對齊；華語沒有空白，chrF++ 的詞 n-gram 退化成整句一個詞；逐句統計加總要等於整批分數（bootstrap 靠這個） | `test_metrics.py` |
| score | sapolita 一段回兩列，族語列才是 ASR、華語列是它自己接的翻譯；受訪者講華語時沒有族語字幕、sapolita 照樣硬聽成阿美語，過半落在族語字幕底下的段才算「族語字幕時段」；整集接成一條算 CER 是 3 萬 × 3 萬字的編輯距離、跑不動，要切塊；sapolita 在開會了切得很碎（068 集 1,034 段、中位數 1.5 秒），照段歸字幕的話跨段字幕整條歸到一邊、068 集 WER 被量成 118%，所以只在沒有字幕跨過的段界切、併到 30 秒以上；字幕一條接一條沒有乾淨段界時 120 秒也要硬切；sapolita 沒出段的地方有族語字幕是漏聽、算刪除；華語段拿掉時落在裡面的零星族語字幕一起拿掉，不可只拿掉辨識結果；阿美語 o／u 不分音位，sapolita 在海岸／秀姑巒的集也約 40% 寫成 u（替換錯誤前四名 no→nu、ko→ku、to→tu、o→u），合併後的數字只當敏感度分析；翻譯還沒跑完就算分時缺翻譯的句要報出來；bootstrap 種子固定、重跑同一個區間；逐集 CER 表的合計要用錯誤數與參考字元數加總再除，不可平均各集 CER（082 只有 1.5 萬字、105 有 2.9 萬字） | `test_score.py` |

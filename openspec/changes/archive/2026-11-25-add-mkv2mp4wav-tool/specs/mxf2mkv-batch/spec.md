## MODIFIED Requirements

### Requirement: 執行紀錄與對照表

每次執行 MUST 產出兩份檔案：一份收錄每支的外部指令錯誤輸出全文，一份是機器可讀的對照表。兩份 MUST 放在以**來源資料夾名稱**命名的目錄底下，讓同一個來源的歷次執行聚在一起；檔名帶執行的日期時間與來源名稱。系統 MUST NOT 覆寫既有的紀錄檔；檔名相撞時加後綴。

對照表 MUST 在每一支處理完畢（成功、失敗、跳過或中斷）時就寫入，不得等整批結束才寫；寫入過程中斷時，檔案 MUST 仍是前一次寫入的完整內容，不得只寫一半。

#### Scenario: 落點與命名

- **WHEN** 對 `2月原始mxf檔` 執行批次
- **THEN** 紀錄放在該來源專屬的目錄底下
- **AND** 兩份檔案的檔名都帶執行的日期時間與來源名稱

#### Scenario: 同一個來源跑第二次

- **WHEN** 同一個來源資料夾再跑一次
- **THEN** 新的兩份檔案放進同一個目錄
- **AND** 前一次的兩份檔案完全沒有被改動

#### Scenario: 同一分鐘內跑兩次

- **WHEN** 要產生的紀錄檔名與既有檔案相同
- **THEN** 加上後綴另建新檔
- **AND** 既有檔案沒有被改動

#### Scenario: 對照表的內容

- **WHEN** 一支處理完畢（成功、失敗或跳過）
- **THEN** 對照表為它留一筆，載明來源相對路徑與位元組數、遠端路徑與位元組數、來源音軌數、封存保留的音軌數、音軌是否重複、音訊是否逐位元相符、耗時與結果
- **AND** 對照表是排版過、中文不轉義、鍵有排序的 JSON

#### Scenario: 做到一半當掉

- **WHEN** 批次做完第 N 支後，在第 N+1 支進行中被強制結束（未經正常收尾）
- **THEN** 對照表已載明前 N 支，且是完整可解析的 JSON

#### Scenario: 寫入對照表時中斷

- **WHEN** 重寫對照表的過程中程序被停掉
- **THEN** 磁碟上的對照表仍是上一次寫入的完整內容

「音軌是否重複」這一欄是日後接目錄、決定拿哪一條音軌做語音辨識的依據。

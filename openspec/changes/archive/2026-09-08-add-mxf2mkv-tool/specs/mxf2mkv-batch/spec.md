## Purpose

把本機一個資料夾（通常是插著的隨身硬碟）底下的母帶逐支轉成封存 mkv 並送上 SFTP，遠端結構照著來源擺。不需要知道每支影片是哪一集，所以還沒登記進目錄的檔案也轉得動。

## ADDED Requirements

### Requirement: 只認來源資料夾，不查任何登記簿

批次 MUST 只從命令列給的來源資料夾決定要做哪些檔案。系統 MUST NOT 讀取節目目錄、`smkul.csv` 或 inventory，也 MUST NOT 因為某支影片沒有登記就跳過它。

隨身硬碟不能一直插著除錯，所以先轉完再認 catalogue（使用者裁定 2026-09-05）。

#### Scenario: 沒登記的檔案照轉

- **WHEN** 來源資料夾裡有一支從未出現在任何登記簿的母帶
- **THEN** 這支照樣被轉檔並上傳

#### Scenario: 遞迴掃描並只挑母帶

- **WHEN** 來源資料夾底下還有子資料夾
- **THEN** 子資料夾裡的 `.mxf` 一併納入
- **AND** 非 `.mxf` 的檔案一律略過

### Requirement: 遠端結構鏡射來源

遠端路徑 MUST 是「遠端根」＋「來源資料夾的最後一層名稱」＋「該檔案相對於來源資料夾的路徑」，副檔名換成 `.mkv`，其餘一字不改。遠端根預設為 `/home/mkv-raw`。

#### Scenario: 根目錄下的檔案

- **WHEN** 來源是 `/media/hong/USB/2月原始mxf檔`、檔案是 `a.mxf`
- **THEN** 遠端路徑為 `/home/mkv-raw/2月原始mxf檔/a.mkv`

#### Scenario: 子資料夾裡的檔案

- **WHEN** 同一個來源底下的檔案是 `夜間/b.mxf`
- **THEN** 遠端路徑為 `/home/mkv-raw/2月原始mxf檔/夜間/b.mkv`

#### Scenario: 遠端資料夾還不存在

- **WHEN** 遠端路徑的上層資料夾尚未建立
- **THEN** 由外而內逐層建立
- **AND** 已存在的層不算失敗

#### Scenario: 路徑含危險字元

- **WHEN** 來源檔名含引號、反斜線或控制字元
- **THEN** 這支拒絕處理並記為失敗，不送出任何遠端指令

### Requirement: 不影響既有的族語新聞封存

批次 MUST NOT 讀取、覆寫或刪除既有封存位置（`/home/news/mkv/`）底下的任何檔案。來源與既有封存重複的影片 MUST 照常轉檔並放進自己的遠端根。

#### Scenario: 同一支影片兩邊都有

- **WHEN** 來源的某支母帶在既有封存已經有一份對應的 mkv
- **THEN** 批次仍然轉檔並上傳到自己的遠端根
- **AND** 既有封存的那一份完全沒有被讀寫

### Requirement: 一支轉完就上傳，上傳後才算完成

每支 MUST 依序完成「轉檔 → 驗音訊 → 去重複音軌 → 上傳 → 比對遠端位元組數」才算完成，再進行下一支。

上傳 MUST 先送到一個**暫用的遠端名稱**，位元組數與本機成品相符後才改成最終名稱。傳輸中斷時 MUST NOT 有任何檔案佔用最終名稱。

最終名稱是下一次執行判斷「這支做完了沒有」的唯一依據，而成品的位元組數要轉完才知道——轉檔正是跳過機制要省下的那二十分鐘。所以「完整」這件事必須由**名字**本身承載，不能靠事後比對大小。

#### Scenario: 位元組數相符才改成最終名稱

- **WHEN** 上傳結束且遠端暫用名稱的位元組數等於本機成品
- **THEN** 改名為最終名稱
- **AND** 這支記為成功
- **AND** 本機的中間產物與成品全部刪除

#### Scenario: 位元組數不符

- **WHEN** 上傳結束但遠端位元組數與本機不同
- **THEN** 不改名，最終名稱不會出現
- **AND** 這支記為失敗

#### Scenario: 傳輸中途斷線

- **WHEN** 上傳進行到一半中斷
- **THEN** 殘留的檔案帶著暫用名稱
- **AND** 最終名稱不存在

### Requirement: 已完成的跳過

批次 MUST 可以重跑。遠端最終名稱已存在且不是零位元組時，該支 MUST 跳過。

#### Scenario: 遠端已有最終名稱

- **WHEN** 遠端目標路徑已存在且大於零位元組
- **THEN** 這支跳過，不重新轉檔
- **AND** 記為「已存在」而非成功或失敗

#### Scenario: 遠端只有半截的暫用檔

- **WHEN** 遠端只有帶暫用名稱的殘留檔案
- **THEN** 這支重新處理

### Requirement: 一支失敗不影響其他支

任何一支失敗時，批次 MUST 記錄失敗原因並繼續下一支。批次跑完後，只要有任何一支失敗，整體離開碼 MUST 為非零。

#### Scenario: 中間一支壞掉

- **WHEN** 第三支的音訊驗證不相符
- **THEN** 記錄該支失敗與原因
- **AND** 第四支照常開始
- **AND** 批次跑完後離開碼為非零

#### Scenario: 全部成功

- **WHEN** 每一支都成功或跳過
- **THEN** 離開碼為零

### Requirement: 工作目錄每次執行各自獨立

系統 MUST 為每次執行建立自己的工作目錄，讓多個執行可以同時進行而不互相覆蓋。正常結束時工作目錄 MUST 刪除；有失敗時 MUST 保留，並在紀錄中寫出它的路徑。

#### Scenario: 兩個執行同時跑

- **WHEN** 對兩個不同的來源資料夾同時各起一個執行
- **THEN** 兩者各自使用不同的工作目錄
- **AND** 任一方的中間產物都不會被另一方讀寫或刪除

#### Scenario: 失敗時保留現場

- **WHEN** 批次結束時有任何一支失敗
- **THEN** 工作目錄保留
- **AND** 紀錄的最後寫出工作目錄的路徑

### Requirement: 執行紀錄與對照表

每次執行 MUST 產出兩份檔案：一份收錄每支的外部指令錯誤輸出全文，一份是機器可讀的對照表。兩份 MUST 放在以**來源資料夾名稱**命名的目錄底下，讓同一個來源的歷次執行聚在一起；檔名帶執行的日期時間與來源名稱。系統 MUST NOT 覆寫既有的紀錄檔；檔名相撞時加後綴。

#### Scenario: 落點與命名

- **WHEN** 對 `2月原始mxf檔` 執行批次
- **THEN** 紀錄放在該來源專屬的目錄底下
- **AND** 兩份檔案的檔名都帶執行的日期時間與來源名稱

#### Scenario: 同一個來源跑第二次

- **WHEN** 同一個來源資料夾再跑一次
- **THEN** 新的兩份檔案放進同一個目錄
- **AND** 前一次的兩份檔案完全沒有被改動

#### Scenario: 同一分鐘內跑兩次

- **WHEN** 要產生的紀錄檔名與既有檔案相同
- **THEN** 加上後綴另建新檔
- **AND** 既有檔案沒有被改動

#### Scenario: 對照表的內容

- **WHEN** 一支處理完畢（成功、失敗或跳過）
- **THEN** 對照表為它留一筆，載明來源相對路徑與位元組數、遠端路徑與位元組數、來源音軌數、封存保留的音軌數、音軌是否重複、音訊是否逐位元相符、耗時與結果
- **AND** 對照表是排版過、中文不轉義、鍵有排序的 JSON

「音軌是否重複」這一欄是日後接目錄、決定拿哪一條音軌做語音辨識的依據。

### Requirement: 序列處理，不自行平行

批次 MUST 一次只處理一支。系統 MUST NOT 提供在單一執行內平行轉檔的選項。

來源通常是單顆外接硬碟，同時讀兩支數十 GB 的檔案會互相搶 I/O，反而比逐支慢。要平行時由使用者對不同的來源資料夾各起一個執行。

#### Scenario: 逐支進行

- **WHEN** 來源資料夾有多支母帶
- **THEN** 同一時間只有一支在轉檔

### Requirement: 試跑不動任何檔案

系統 MUST 提供試跑模式，列出每支會被怎麼處理、成品會送到哪個遠端路徑，而不建立、修改或刪除任何本機或遠端檔案。

#### Scenario: 試跑

- **WHEN** 以試跑模式執行
- **THEN** 列出每支的來源路徑、對應的遠端路徑、以及會跳過還是會處理
- **AND** 沒有任何檔案被建立、修改或刪除
- **AND** 沒有送出任何會改變遠端狀態的指令

## Purpose

把廣播母帶轉成可長期保存、又能重跑字幕流程的封存 mkv：視訊有損但留足餘裕，音訊逐位元不動，音軌不論幾條都不會被靜靜丟掉。族語新聞封存與隨身硬碟批次共用這一份契約。

## ADDED Requirements

### Requirement: 來源只讀一次

封存一支母帶時，系統 MUST 只完整讀取來源檔案一次，並在同一次讀取中同時產出封存檔與**來源每一條音軌的指紋**。後續的驗證與音軌去留 MUST 只讀本機的封存產物，不得再回頭讀來源。

來源多半在慢速媒體上（USB 隨身硬碟、SFTP 掛載），每多讀一次就是一支影片大小的成本。

#### Scenario: 一趟產出封存與指紋

- **WHEN** 對一支有 N 條音軌的母帶執行封存編碼
- **THEN** 產出一個含來源全部 N 條音軌的封存檔
- **AND** 同時產出 N 個指紋，第 i 個對應來源的第 i 條音軌
- **AND** 整個過程對來源檔案只有一次完整讀取

#### Scenario: 驗證不重讀來源

- **WHEN** 系統要判斷封存的音訊是否與來源相符
- **THEN** 比對的兩邊分別是前一步留下的來源指紋、以及對封存檔算出的指紋
- **AND** 不對來源檔案發出任何讀取

### Requirement: 音訊逐位元相符才算封存成功

封存檔每一條音軌的內容 MUST 與來源對應音軌逐位元相同。任何一條不符，這支的封存 MUST 判定為失敗，且失敗的產物不得留在正式輸出位置。

這個語料庫的存在目的是訓練聲學模型，音訊一旦被重新量化就失去價值。判準是逐位元，不設「差多少算相同」的門檻。

#### Scenario: 相符則成功

- **WHEN** 封存檔所有音軌的指紋都與來源對應音軌相同
- **THEN** 這支封存判定為成功

#### Scenario: 不符則失敗且不留成品

- **WHEN** 任何一條音軌的指紋與來源不符
- **THEN** 這支封存判定為失敗
- **AND** 錯誤訊息指出是哪一條音軌、兩邊的指紋各是什麼
- **AND** 半成品不會出現在正式輸出位置

#### Scenario: 來源音訊本來就不是整數 PCM

- **WHEN** 來源音軌解碼出來是浮點取樣（例如 AAC）
- **THEN** 該音軌以原封不動的方式搬進封存檔，不重新編碼
- **AND** 相符的判準改為比對搬運前後的封裝資料，而非解碼後的取樣

浮點轉整數必然捨入，那個捨入是真實且可重現的資料改變，不能算相符。

### Requirement: 音軌數量不設上限

系統 MUST 處理來源的每一條音軌，不論幾條。任何一條來源音軌都不得在沒有訊息的情況下被排除在封存與驗證之外。

#### Scenario: 三條以上音軌要出聲

- **WHEN** 來源有三條或更多音軌
- **THEN** 全部音軌都進入封存與指紋計算
- **AND** 執行紀錄明白寫出「這支有幾條音軌」

#### Scenario: 只有一條音軌

- **WHEN** 來源只有一條音軌
- **THEN** 封存檔有一條音軌，不做任何去留判斷

### Requirement: 重複音軌只留一條

當來源有多條音軌、且其中若干條彼此逐位元相同時，封存檔 MUST 只保留其中一條，其餘捨去。只要有任一條與其他條**不**相同，該條 MUST 保留。

實測 63 支族語新聞封存，35 支的兩軌逐位元相同（是同一份訊號的兩個聲道），28 支不同。不同的那些差在最低幾個位元，但差異是真的，靜靜丟掉一條不能接受。

#### Scenario: 兩軌相同

- **WHEN** 來源兩條音軌逐位元相同
- **THEN** 封存檔只有一條音軌
- **AND** 執行紀錄寫明「兩軌相同，留一軌」

#### Scenario: 兩軌不同

- **WHEN** 來源兩條音軌不是逐位元相同
- **THEN** 封存檔保留兩條音軌
- **AND** 執行紀錄寫明「兩軌不同，兩條都留」

#### Scenario: 三軌中兩條相同

- **WHEN** 來源三條音軌中有兩條逐位元相同、第三條不同
- **THEN** 封存檔保留兩條音軌：相同的那組留一條，加上不同的那一條

### Requirement: 視訊編碼參數不因這次改動而變

封存的視訊 MUST 維持既有實測結論下的參數：H.264、CRF 23、`yuv420p`，解析度與影格率照原樣不縮放、不抽幀。這些數字是拿字幕辨識字元錯誤率量出來的，CRF 32 會掉整句字幕，餘裕本身就是目的。

#### Scenario: 預設參數

- **WHEN** 沒有指定編碼參數
- **THEN** 使用 CRF 23、`yuv420p`
- **AND** 產出的影片解析度與影格率與來源相同

#### Scenario: 呼叫端可指定

- **WHEN** 呼叫端指定了 CRF 或像素格式
- **THEN** 以指定的為準
